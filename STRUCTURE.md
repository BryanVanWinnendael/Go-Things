# Source layout

Every app uses the same shape. `mygo.json` stays at the app root; the Go
entry point is named by its `"main"` field, so no Go source needs to sit next
to the config.

```
<app>/
  mygo.json        config and version — edit here to bump the app
  go.mod, go.sum   module files
  resources/       icon.png and previewN.png (pictures only)
  cmd/<app>/       thin main(), calls internal/app.Main()
  internal/        the actual program
  build/           generated by .\build.ps1, ignored by Git
```

The version is read from `mygo.json`. `manifest.go` at the root of Go Post and
Go Mail embeds that file so the UI shows the same version the installer was
built with (`go:embed` cannot reach a parent folder from a subpackage).

## go-hub

```
cmd/go-hub/                  process entry point
internal/app/                window, navigation, store/library/about/detail pages, widgets, install flow
internal/catalog/            catalog.json types, fallback, validation, download/cache
internal/install/            Windows uninstall-key reads, setup/uninstall/launch
internal/settings/           theme preference
internal/theme/              palettes and theme construction
```

## go-post

```
cmd/go-post/                 process entry point
internal/app/                app state, UI pages, menus, theme editor, import/export, variable UI
internal/core/               data model, store, HTTP client, auth, certificates, query and header helpers
```

## go-mail

```
cmd/go-mail/                 process entry point
internal/app/                app state, mail UI, settings, theme editor, compose, signatures, logos
internal/mail/               IMAP/SMTP engine, message building and signature rendering
```

Tests live beside the code they test. Build outputs never get committed;
`.\build.ps1` leaves each setup in `<app>/build/windows-amd64/` for attaching
to a GitHub release.
